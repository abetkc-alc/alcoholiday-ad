# ALCOHOLIDAY 広告事業（BARのおすすめ紹介）

## 結論

- 全国の BAR から「おすすめ商品」を受け付け、ALCOHOLIDAY の SNS（Instagram・TikTok・X ＠alcoholiday25）で**動画で紹介**する
- 投稿は**1日2回**：**11時〜13時頃**（予約投稿の時刻 **12:00**）と **16時〜18時頃**（予約投稿の時刻 **17:00**）。受付ページの表記もこのとおり。1枠に1店（2026-10-04 変更。朝7:30・夕方17:00 → 16:00〜17:00 の1回 → いまの2回）
- 申し込みは**1か月先まで**。**締め切りは投稿の3時間前**（2026-10-04 変更。当日の枠も申し込める。Code.gs の ORDER_BEFORE_HOURS・BOOK_MONTHS）
  - **お客さんの承認の締め切りは投稿の2時間前**（2026-10-04 社長の決定。APPROVE_BEFORE_HOURS）。締め切りぎりぎりの申し込みだと、動画づくり・社長の確認・承認を1時間でする必要があるので、当日・翌日の申し込みが来たらすぐ社長に知らせる
- **動画はお客さん（BAR）が自分で撮る**：5秒くらいの動画を**3本**（①お店の雰囲気 ②おすすめ商品＝いちばん売りたいもの ③自由）と、それぞれの**説明文**を受付サイトで送ってもらう（2026-10-04 に写真＋AI案内役の形から変更）
- KAYO が説明文を5秒で読める長さに整え、3本をつないで**ナレーション（AIの読み上げ）と字幕**を入れる
- ナレーションの声は**案内役4人**：**A＝ローズ**（明るく親しみやすい）／**B＝ラフィ**（クールで大人っぽい）／**C＝アイラ**（ゆっくり落ち着いた）／**D＝アルビン**（男性。2026-10-04 追加）。**動画には出ず、声だけ担当**。声は Google の読み上げ（社長が聞き比べて決定）。プログラムの中では A〜D の記号で区別する
- お客さん（BAR）は**トップページで会員登録・ログイン**（メール＋パスワード）→ **受付ページ**で申し込み → **パソコンが自動で動画をつくり、承認のお願いメールまで送る**（約10分。2026-10-04 社長の指示で社長の確認は挟まない）→ お客さんが**承認ページ**で承認 → **指定の時刻に自動で投稿**
- **動画の直しは1回まで**。直しの依頼も自動で直して送る。直したあとは「直したあと」「直す前」の2本から選んで承認してもらう
- 会員の一覧は受付台帳の「**会員**」シート（登録したらすぐ使える。社長には「新しい会員」のメール。止めるときは「状態」を「停止」）。パスワードはそのまま保存せず、変換した値だけを残す。5回まちがえると15分ログインできない。忘れたらトップページから自分で再設定（メールのリンク・1時間有効）
- 承認がない動画は投稿しない（期限が過ぎたら自動で「期限切れ」）

## 全体の流れ

```
BAR（お客さん）                 Google（受付台帳）                パソコン（KAYO）
──────────────                 ────────────────                ──────────────
①受付サイトで申し込み ───────▶ 台帳に「受付」・動画3本を保存
                                 社長にメール ──────────────▶ ②「KAYO、BAR広告の新しい依頼を確認して」
                                                                  pull で取り込み（状態「制作中」）
                                                                  scripts（ナレーション）→ editing で動画
                                                                ③ 社長が動画を確認して OK
                                 ◀──────────────────────────── deliver（状態「承認待ち」）
④承認ページのメールが届く ◀─── お客さんにメール
  「承認する」を押す ─────────▶ Upload-Post に予約（状態「予約済み」）
                                 指定の時刻に IG・TikTok・X へ自動投稿
⑤「投稿しました」メール ◀───── 1時間ごとの見回りで「投稿済み」
```

- **2026-10-04 から ②③ は自動**（`tools/bar_auto.py` を Windows のタスク スケジューラーで5分ごと）。社長の確認は挟まない（社長の指示）。社長には受付・承認などのメールが届き、台帳で様子が見える
- 「直してほしい」が押されたら → 状態「修正依頼」→ 社長にメール → **自動で直して、もう一度承認のお願い**（1回まで）。自動で直せなかったときだけ「**KAYO、BAR広告の修正依頼を確認して**」
- 社長の管理画面は **受付台帳（Google スプレッドシート）**。状態・履歴が全部見える

## 状態の種類（受付台帳の「状態」の列）

| 状態 | 意味 |
|---|---|
| 受付 | お客さんが申し込んだ。まだ KAYO が取り込んでいない |
| 制作中 | KAYO が動画をつくっている |
| 承認待ち | 動画をお客さんに送った。承認を待っている |
| 修正依頼 | お客さんが「直してほしい」を押した |
| 承認済み → 予約済み | 承認された → Upload-Post に予約できた |
| 予約エラー | 予約に失敗。履歴に理由。投稿時刻の前なら1時間ごとに自動でやり直す |
| 投稿済み | 投稿時刻を過ぎた（お客さんに「投稿しました」メール済み） |
| 期限切れ | 投稿の2時間前までに承認がなかった（投稿しない） |
| キャンセル | 取りやめ（枠が空く） |

## KAYO の作業手順

### 自動制作（2026-10-04 社長の指示：申し込み → 承認のお願いメールまで自動）

- `python 09_広告事業/tools/bar_auto.py` が、「受付」の申し込みを取り込み → Claude（`claude -p`）が台本と投稿文 → 動画を組み立て → 投稿文の決まりを確認 → **お客さんに承認のお願いメール**まで行う。社長の確認は挟まない（社長の指示）。SNS への投稿は、これまでどおりお客さんの承認のあとだけ
- **直しの依頼（修正依頼）も自動**（2026-10-04 社長の指示）。お客さんのコメントに合わせて Claude が直し、もう一度承認のお願いを送る。できなかったものは「修正依頼」のまま残る（`.自動の直しができなかった` の印。同じ依頼では二度とためさない）→ 下の手順で KAYO が手で直す。手で試す：`python 09_広告事業/tools/bar_auto.py <受付番号> fix "依頼の文" --dry`
- 背景の音楽は `素材/音楽の札.json` の札で選ぶ（use=false の曲は使わない。曲を足したら札も足す）
- 記録：`自動制作ログ.md`。うまくいかなかった案件は「制作中」のまま残る → 下の手順で KAYO が手で仕上げる
- ファイルは版ごとに別名：`制作-v2.json`・`投稿文-v2.json`・`台本-v2.md`・`動画/bar-ad-v2.mp4`
- 試し：`python 09_広告事業/tools/bar_auto.py <受付番号> --dry`（動画までつくり、メールは送らない）
- 5分ごとに動かすには Windows のタスク スケジューラーに `tools/bar_auto_run.vbs` を登録する（2026-10-04 社長の OK で登録済み：タスク名「ALCOHOLIDAY BAR広告 自動制作」。止めたいときはタスク スケジューラーでこのタスクを「無効」にする）。動いた記録は `案件/自動制作の記録.txt`。パソコンの電源が入っているときだけ動く

### 「KAYO、BAR広告の新しい依頼を確認して」

1. `python 09_広告事業/tools/bar_sync.py pull` → `案件/<受付番号>/` に `order.json`・`依頼メモ.md`・`素材/video1〜3`（.mov や .mp4）ができる
   - お試し版の依頼ファイルは `python 09_広告事業/tools/bar_sync.py local <ダウンロードの BAR依頼-TEST-….json>`
2. 動画3本を確認する（数か所を書き出して見る）。商品がはっきり写っているか・暗すぎないか・ほかの店のロゴや**お客さんの顔**が映っていないか・ブレがひどくないか。問題があれば社長に相談（撮り直しをお願いすることもある）
3. **scripts**：お客さんの説明文から、動画1本ごとの**ナレーション**（下の「台本のきまり」）と投稿文をつくる → `案件/<受付番号>/台本.md` と `投稿文.json`
4. 各動画の**使うところ（start）**を決める。一番よいところから約4.5秒。横向きの動画もそのまま使える（ぼかした背景の上に置かれる）
5. `案件/<受付番号>/制作.json` を書き、`python 09_広告事業/tools/build_bar_ad.py 案件/<受付番号>/制作.json`
   - ナレーションは自動でつくられる（`tools/narrate.py`。声は order の「案内役」A/B/C。「おまかせ」なら店の雰囲気で選ぶ）
   - 「動画○が足りません」と出たら、ナレーションを短くするか start を前にする（静止やループで伸ばさない）
6. 動画の数か所を書き出して目で確認（字幕・商品名・店名のつづり・PR表示・締め）。声も聞いて、読み間違い（店名・地名・数字）がないか確かめる。読み間違いはナレーションをひらがなで書いて直す（字幕はそのまま）
7. **社長に確認してもらう**（動画の場所と投稿文を見せる）。OK が出るまで deliver しない
8. 社長の OK → `python 09_広告事業/tools/bar_sync.py deliver <受付番号> <動画> <投稿文.json>` → お客さんに承認のお願いが届く
9. `依頼メモ.md` に記録を書く

### 「KAYO、BAR広告の修正依頼を確認して」

- **直しは1回まで**（2026-10-04 社長の指示）。直した動画を deliver すると、前の動画と投稿文が台帳の「前の動画」「前の投稿文」に残り、承認ページはお客さんが2本から選んで承認する形になる（2回目の修正依頼はできない）


1. `python 09_広告事業/tools/bar_sync.py fixes` でコメントを読む
2. 直した動画を**別名（v2, v3…）**でつくる → 社長の確認 → deliver（同じ受付番号でもう一度送れる）

## 台本のきまり（scripts）

- ナレーションは**動画1本につき1文・4秒以内（25文字まで）**。お客さんの説明文から一番の売りを選んで短くする（説明にないことは足さない）
  - 動画1：お店の場所と雰囲気。投稿はお昼か夕方なので「今夜はここへ」「今夜の一杯は」のように**その日の夜に行きたくなる**言い方
  - 動画2：おすすめ商品の一番の売り（素材・季節・限定など）
  - 動画3：お店やマスターの魅力で締める
- 承認ページで、お客さんが整えたあとの文を動画で確認できる
- 説明文に**ほかの会社や商品の名前**があっても、ナレーション・字幕には入れない（広告に他社の名前を出さない）
- 動画の長さ（多くは5秒前後）に声が入りきらないことがある。`build_bar_ad.py` が「足りません」と止めたら、文を短くする
- 字幕は1つのナレーションを2つくらいに分ける（1行15文字まで）
- **お客さんが受付ページで書いた文があれば、それをもとにする**（依頼メモの「SNS に載せる文」。order の「お客さんの投稿文」）。中身は変えすぎず、決まった文（#PR・提供・注意書き・住所・営業時間・電話）を足す。空なら KAYO が書く
- 投稿文は `投稿文.json` に3つ：`{"instagram": "…", "tiktok": "…", "x": "…"}`
  - 3つとも **「#PR」** と **「提供：店名」** を入れる（ステルスマーケティング規制。入れないと `bar_sync.py` が止める）
  - お酒の注意書き「お酒は20歳になってから。飲酒運転は法律で禁止されています。」を入れる
  - **お店の住所・営業時間・電話番号は3つとも必ず入れる**（2026-10-04 社長の指示。締め画像の「紹介したお店の詳細はキャプションから。」に合わせる）。店名・お店の SNS も入れる
  - お客さんの文（受付ページの入力欄は1つ）は **Instagram にほぼそのまま**使い、**TikTok と X はそれを短くまとめる**
  - **X は280まで**（日本語は1文字を2と数えるので、およそ140文字）。決まった文と店の情報だけで100文字ほど使うので、本文はひとことにする。X には URL を入れない（Upload-Post の追加料金がかかるため）
  - できたら `python 09_広告事業/tools/bar_sync.py check <受付番号> 案件/<受付番号>/投稿文.json` で確かめる（#PR・提供・注意書き・住所・営業時間・電話・X の長さ。deliver も同じ確認をして、足りなければ止まる）
  - ハッシュタグ例：#BAR #バー #今夜の一杯 #（地域名）バー #ALCOHOLIDAY

## 受付サイトのいまの形（2026-10-04 時点のまとめ）

| ページ | ファイル | 中身 |
|---|---|---|
| トップページ | `top.html` | 紹介（Pinterest ふう・ポスターの部屋の写真）・会員登録・ログイン・パスワード再設定。**ログインしたら、そのまま申し込みのページに切り替わる**（ボタンは1回。開いているあいだ「申し込みのページを開いています…」） |
| 申し込み（会員だけ） | `form.html` | ①お店のこと（会員情報が入っている）②おすすめ商品（名前40字・説明300字・値段・数量限定）③動画3本（各5秒程度・説明100字）④SNS に載せる文（1つ）⑤声の種類（▶ 声を聞く）⑥投稿する日（11時〜13時頃＝12:00／16時〜18時頃＝17:00・1か月先まで・締め切り3時間前）⑦確認（責任の文・直しは1回まで）→ 受け付けた画面。商品名の欄は文字の量に合わせて広がる。ログアウトはトップページへ移って行う |
| 承認ページ | `review.html` | 動画（ページの中で直接再生）と SNS の文を見て「承認する」か「直してほしいところがある（1回まで）」。**直したあとは2本から選んで承認**（承認の締め切り2時間前） |
| 共通 | `css.html`・`common.html`・`logo.html`・`photos.html` | 見た目（Pinterest ふう：白・赤い丸いボタン #E60023）・🎤 話して入力・文字数・ロゴ・写真 |

- 会員：メール＋パスワード。登録したらすぐ使える（社長にメール）。受付台帳の「会員」シート。止めるときは「状態」を「停止」
- 動画：お客さんの動画3本＋ナレーション（ローズ／ラフィ／アイラの声）＋字幕＋商品名・店の情報＋（数量限定の一文）＋締め画像（`素材/ending-bar-v4.jpg`：アマゾンなし・赤枠赤文字「紹介したお店の詳細はキャプションから。」）
- 投稿文：住所・営業時間・電話番号は3つとも必ず。`bar_sync.py check` で確かめる
- お試し版（パソコンの中だけ）：KAYO の作業用フォルダの `make_preview.py`（トップ・申し込み）と `make_review_preview.py`（承認ページ）でつくる
