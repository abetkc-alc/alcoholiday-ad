# ALCOHOLIDAY 広告事業（BARのおすすめ紹介）

## 結論

- **2026-10-10 社長の指示で形を変更：「ショート動画作成」**。全国の BAR から「おすすめ商品」の動画3本と説明を受け付け、紹介動画をつくって**お客さんにダウンロードしてもらう**。**投稿はお客さんが自分の SNS アカウントで行う**（ALCOHOLIDAY のアカウントには載せない。Upload-Post の自動投稿はやめた）
  - 理由：お店のフォロワーに直接届くほうが来店につながりやすい／ALCOHOLIDAY のアカウントでの投稿は本数の制限と責任がある。この事業の目的は、**ALCOHOLIDAY の物販のための認知度アップ**
  - お客さんは**投稿文が欲しい SNS をえらぶ**（Instagram・TikTok・X から1つ以上）。投稿文は**商品の説明をもとに自動でつくる**（申し込みページに入力欄はない）。どの投稿文も最後に「**提供：アルコホリディ**」と **https://www.alcoholiday.org/** を必ず付ける（プログラムが付ける）
  - 確認ページで「**この動画に決める**」を押すと、**動画のダウンロードのリンク**と**えらんだ SNS ごとの投稿文**がメールで届く（状態「お渡し済み」。確認ページにも「動画をダウンロード」ボタンが出る）
  - **確認ページは、決める前から動画をダウンロードできる**（動画の下の「⬇ 動画をダウンロード」。直したあとは2本それぞれの下にボタン）。**確認ページは期限（受付から24時間）を過ぎると見られなくなる**（「公開期間は終わりました」と出る。動画のファイルは消さない。メールのダウンロードのリンクは期限のあとも使える）。2026-10-10 社長の指示
  - 「動画ができました」メールには、期限の日時（例：10月11日 11:50）を書き、「この日時までにお選びいただけない場合、お渡しは終了・ページも見られなくなる」と知らせる（お客さんに見せる日時は jaTime_ の形）
  - **お客さんに送るメールはすべて、最後に ALCOHOLIDAY のサイト（https://www.alcoholiday.org/ ）と Amazon のお店の URL を付ける**（2026-10-10 社長の指示。Code.gs の MAIL_LINKS。社長あてのお知らせには付けない）
  - 動画を決める期限は**受付から1日**（APPROVE_DAYS。2026-10-10 社長の指示で7日→1日。過ぎたら期限切れ・お渡ししない。1時間ごとの見回りで期限切れにする）
- **無料版と有料版**（2026-10-10 社長の指示。受付台帳の「プラン」の列）
  - **無料版**：動画①〜③のあいだ、**画面の上下に ALCOHOLIDAY のロゴを透かし**で入れる＋最後に**締め画像とナレーション**（約18秒）
  - **有料版（500円の予定）**：透かしと締めはなし。**最後の2.5秒だけ右下に小さく「created by」と ALCOHOLIDAY のロゴ**（約13.5秒）
  - **お支払いの仕組みはまだない**。受付はすべて「無料」。有料版にするときは、自動制作の前に台帳の「プラン」を「有料」に変える
- 前の形（2026-10-06〜10-09）：お客さんの承認から2時間以内に、ALCOHOLIDAY の SNS（@alcoholiday25）へ Upload-Post で自動投稿（同じ SNS は前後2時間あけ・1日6本まで）。その前（〜10-05）は1日2回の枠をお客さんがえらぶ形
- **動画はお客さん（BAR）が自分で撮る**：5秒くらいの動画を**3本**（①お店の雰囲気 ②おすすめ商品＝いちばん売りたいもの ③自由）と、それぞれの**説明文**を受付サイトで送ってもらう（2026-10-04 に写真＋AI案内役の形から変更）
- KAYO が説明文を5秒で読める長さに整え、3本をつないで**ナレーション（AIの読み上げ）と字幕**を入れる
- ナレーションの声は**案内役4人**：**A＝ローズ**（明るく親しみやすい）／**B＝ラフィ**（クールで大人っぽい）／**C＝アイラ**（ゆっくり落ち着いた）／**D＝アルビン**（男性。2026-10-04 追加）。**動画には出ず、声だけ担当**。声は Google の読み上げ（社長が聞き比べて決定）。プログラムの中では A〜D の記号で区別する

## 全体の流れ

```
BAR（お客さん）                 Google（受付台帳）                パソコン（KAYO）
──────────────                 ────────────────                ──────────────
①受付サイトで申し込み ───────▶ 台帳に「受付」・動画3本を保存
                                 社長にメール ──────────────▶ ②「KAYO、BAR広告の新しい依頼を確認して」
                                                                  pull で取り込み（状態「制作中」）
                                                                  scripts（ナレーション）→ editing で動画
                                                                ③ 社長が動画を確認して OK
                                 ◀──────────────────────────── deliver（状態「承認待ち」）
④「動画ができました」メール ◀── お客さんにメール
  確認ページで「この動画に決める」▶ 状態「お渡し済み」
⑤ダウンロードのリンクと         ◀─ お客さんにメール
  SNS ごとの投稿文が届く
⑥お店の SNS に自分で投稿
```

- **2026-10-04 から ②③ は自動**（`tools/bar_auto.py` を Windows のタスク スケジューラーで5分ごと）。社長の確認は挟まない（社長の指示）。社長には受付・承認などのメールが届き、台帳で様子が見える
- 「直してほしい」が押されたら → 状態「修正依頼」→ 社長にメール → **自動で直して、もう一度「動画ができました」メール**（1回まで）。自動で直せなかったときだけ「**KAYO、BAR広告の修正依頼を確認して**」
- 社長の管理画面は **受付台帳（Google スプレッドシート）**。状態・履歴が全部見える

## 状態の種類（受付台帳の「状態」の列）

| 状態 | 意味 |
|---|---|
| 受付 | お客さんが申し込んだ。まだ KAYO が取り込んでいない |
| 制作中 | KAYO が動画をつくっている |
| 承認待ち | 動画をお客さんに送った。お客さんが動画を決めるのを待っている |
| 修正依頼 | お客さんが「直してほしい」を押した |
| お渡し済み | お客さんが確認ページで動画を保存した（お客さんへのメールはなし。2026-10-10〜） |
| 公開終了 | ダウンロード済みで、期限（受付から24時間）が来た。確認ページとダウンロードのリンクを止めた（2026-10-10〜） |
| 期限切れ | 受付から24時間のうちにダウンロードされなかった（リンクを止めた・お客さんにメール） |
| 承認済み・予約済み・予約エラー・投稿済み | 2026-10-09 までの自動投稿の形のときの状態（いまは使わない） |
| キャンセル | 取りやめ（枠が空く） |

## KAYO の作業手順

### 自動制作（2026-10-04 社長の指示：申し込み → 「動画ができました」メールまで自動）

- `python 09_広告事業/tools/bar_auto.py` が、「受付」の申し込みを取り込み → Claude（`claude -p`）が台本と、えらばれた SNS ごとの投稿文 → 投稿文の最後に「提供：アルコホリディ」と URL を付ける → 動画を組み立て（台帳の「プラン」が「有料」なら有料版、それ以外は無料版） → 投稿文の決まりを確認 → **お客さんに「動画ができました」メール**まで行う。社長の確認は挟まない（社長の指示）
- **直しの依頼（修正依頼）も自動**（2026-10-04 社長の指示）。お客さんのコメントに合わせて Claude が直し、もう一度「動画ができました」メールを送る。できなかったものは「修正依頼」のまま残る（`.自動の直しができなかった` の印。同じ依頼では二度とためさない）→ 下の手順で KAYO が手で直す。手で試す：`python 09_広告事業/tools/bar_auto.py <受付番号> fix "依頼の文" --dry`
- 背景の音楽は `素材/音楽の札.json` の札で選ぶ（use=false の曲は使わない。曲を足したら札も足す）
- 記録：`自動制作ログ.md`。うまくいかなかった案件は「制作中」のまま残る → 下の手順で KAYO が手で仕上げる
- ファイルは版ごとに別名：`制作-v2.json`・`投稿文-v2.json`・`台本-v2.md`・`動画/bar-ad-v2.mp4`
- 試し：`python 09_広告事業/tools/bar_auto.py <受付番号> --dry`（動画までつくり、メールは送らない）
- 5分ごとに動かすには Windows のタスク スケジューラーに `tools/bar_auto_run.vbs` を登録する（2026-10-04 社長の OK で登録済み：タスク名「ALCOHOLIDAY BAR広告 自動制作」。止めたいときはタスク スケジューラーでこのタスクを「無効」にする）。動いた記録は `案件/自動制作の記録.txt`。パソコンの電源が入っているときだけ動く

### 「KAYO、BAR広告の新しい依頼を確認して」

1. `python 09_広告事業/tools/bar_sync.py pull` → `案件/<受付番号>/` に `order.json`・`依頼メモ.md`・`素材/video1〜3`（.mov や .mp4）ができる
   - お試し版の依頼ファイルは `python 09_広告事業/tools/bar_sync.py local <ダウンロードの BAR依頼-TEST-….json>`
2. 動画3本を確認する（数か所を書き出して見る）。商品がはっきり写っているか・暗すぎないか・ほかの店のロゴや**お客さんの顔**が映っていないか・ブレがひどくないか。問題があれば社長に相談（撮り直しをお願いすることもある）
3. **scripts**：お客さんの説明文から、動画1本ごとの**ナレーション**（下の「台本のきまり」）と投稿文をつくる → `案件/<受付番号>/台本.md` と `投稿文.json`
4. 各動画の**使うところ（start）**を決める。一番よいところから約4.5秒。横向きの動画もそのまま使える（ぼかした背景の上に置かれる）
5. `案件/<受付番号>/制作.json` を書き、`python 09_広告事業/tools/build_bar_ad.py 案件/<受付番号>/制作.json`
   - ナレーションは自動でつくられる（`tools/narrate.py`。声は order の「案内役」A/B/C。「おまかせ」なら店の雰囲気で選ぶ）
   - 「動画○が足りません」と出たら、ナレーションを短くするか start を前にする（静止やループで伸ばさない）
6. 動画の数か所を書き出して目で確認（字幕・商品名・店名のつづり・PR表示・締め）。声も聞いて、読み間違い（店名・地名・数字）がないか確かめる。読み間違いはナレーションをひらがなで書いて直す（字幕はそのまま）
7. **社長に確認してもらう**（動画の場所と投稿文を見せる）。OK が出るまで deliver しない
8. 社長の OK → `python 09_広告事業/tools/bar_sync.py deliver <受付番号> <動画> <投稿文.json>` → お客さんに承認のお願いが届く
9. `依頼メモ.md` に記録を書く

### 「KAYO、BAR広告の修正依頼を確認して」

- **直しは1回まで**（2026-10-04 社長の指示）。直した動画を deliver すると、前の動画と投稿文が台帳の「前の動画」「前の投稿文」に残り、承認ページはお客さんが2本から選んで承認する形になる（2回目の修正依頼はできない）


1. `python 09_広告事業/tools/bar_sync.py fixes` でコメントを読む
2. 直した動画を**別名（v2, v3…）**でつくる → 社長の確認 → deliver（同じ受付番号でもう一度送れる）

### そのほか

- 一覧：`bar_sync.py list`（状態でしぼる：`list 承認待ち`）
- キャンセル：`bar_sync.py set <受付番号> キャンセル`
- 受付ページの「▶ 声を聞く」の見本を登録：`bar_sync.py voice A 09_広告事業/声見本/A.mp3`（B・C も。本番の声に変えたら見本もつくり直して登録し直す）

### 守ること

- **ALCOHOLIDAY のアカウントには投稿しない**（2026-10-10 社長の指示）。投稿はお客さんが自分のアカウントで行う
- 動画のダウンロードのリンクは、お客さんが確認ページで「この動画に決める」を押したあとにだけ送る
- ファイルは消さない・上書きしない（`build_bar_ad.py` は同じ名前があると止まる）
- 今の形（お客さんの動画＋AIの読み上げ）は Higgsfield を使わないので、1件あたりの費用はほぼかからない。Higgsfield を使うときは社長に確認
